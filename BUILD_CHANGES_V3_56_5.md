# BUILD CHANGES — V3.56.5 «Быстрее: убрали сон поверх провайдера»

Дата: 2026-10-07. Следует за V3.56.4.

## Проблема (владелец)
«Долго всё прогружается, надо чтобы было очень быстро».

## Где реально терялись секунды (по логу Railway)
Задача SpicyAPI: создана 16:52:10, картинка готова 16:52:55 (45 с — это нижняя
граница самого провайдера), а узнали мы о ней только в 16:53:08. Причина —
poll-backoff статуса: старт 2 с, рост ×1.5, потолок **15 с**. После готовности
задачи бот мог спать до 15 секунд впустую. Итог: ~13 с накладных расходов на
каждом фото плюс неограниченный по времени скачивание с R2 (висякий сокет
теоретически держал запрос до 5 минут — дефолт aiohttp).

## Что сделано (services/private_photo_service.py, `_spicyapi_render`)
1. Поллинг статуса стал плотным: старт 1.0 с, рост ×1.25, потолок **3.0 с**.
   recordInfo бесплатный — десяток лишних GET за рендер экономят ~10 с
   пользовательского ожидания на каждой картинке (сцены, «Наедине», косплей,
   студия — все идут через этот рендер).
2. Скачивание готового кадра получило жёсткий таймаут 30 с — зависшая выдача
   R2 больше не растянет ответ за горизонт `SPICYAPI_IMAGE_TIMEOUT` (90 с).

## Что осталось медленным по физике
Сам SpicyAPI рендерит Seedream 5.0 lite ~45–60 секунд — это время провайдера,
его можно срезать только меньшим разрешением (упадёт качество — владелец
выбрал качество) или другим движком. После фикса типичная картинка в приложении:
~50–60 с вместо ~65–75 с.
