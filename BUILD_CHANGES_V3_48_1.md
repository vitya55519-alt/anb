# V3.48.1 — Storefront card media survives redeploys (PostgreSQL)

## Owner request
> «Я поменял карусель, поменял медиа витрину, поменял фото, но после редиплоя я
> вынужден менять каждый раз всё это, а это капец долго.»

Диагноз: из всех витринных вещей только **«📥 Медиа витрины»** (статичное фото /
GIF / WebP / MP4 на карточке героини) хранился **файлом на диске** —
`data/card_media/<id>/card_override.<ext>` (наследие V3.43.3, сделанное до
перехода на БД-хранение). Railway живёт на эфемерном диске: каждый редиплой
стирает эту папку, и витрина каждой героини обнуляется — приходилось грузить
заново руками.

Всё остальное уже переживало деплой, потому что лежит в PostgreSQL: карусель
страницы (`PageGalleryShot`), сгенерированные фото (`PrivateGallery`), бейджи
ачивок (`AchievementBadge`), proactive-медиа (`ProactivePhoto`), медиа чата
(`ChatMedia`).

## Fix
Байты витрины переехали в PostgreSQL по отработанному образцу `ChatMedia`.
Файл на диске остался, но теперь это **кэш, который сам восстанавливается из БД**
при промахе (первый запрос после редиплоя материализует его заново).

- **`models/app_models.py`** — новая модель `CardOverride`
  (`__tablename__ = "card_overrides"`): `character_id` (unique), `ext`,
  `content_type`, `image_bytes` (LargeBinary), `updated_at`.
- **`services/db.py`** — `CardOverride` добавлен в импорт моделей, чтобы
  `create_all()` создал таблицу на проде при старте. Схема не мигрируется
  вручную — достаточно деплоя.
- **`services/webapp_service.py`**
  - `set_card_override()` — пишет байты в БД (upsert по `character_id`) и
    зеркалит на диск для мгновенной отдачи.
  - `character_card_override()` — отдаёт файл с диска, а при его отсутствии
    (после редиплоя) достаёт из `card_overrides` и пересоздаёт файл.
  - `clear_card_override()` — удаляет и файл, и строку БД (иначе кэш молча
    восстановился бы из базы).
  - Публичные сигнатуры не изменились — пины V3.43.3 остались зелёными.

Маршрут `/webapp/card/{id}` и админ-разметка не тронуты. Контент-тип и как
рендерится `<img>`/`<video>` — без изменений.

## Tests
- **`tests/test_v3481_card_media_persistence_static.py`** — 5 проверок: модель и
  регистрация в `db.py`, запись байтов в БД, восстановление из БД при промахе
  диска, удаление строки в `clear_*`, неизменность публичных сигнатур.
- Прогон: **17 failed / 886 passed / 1 error** — точный паритет с базлайном
  (те же 17 предыдущих падений, не связанных с витриной) + 5 новых зелёных.

## Deploy notes
- БД-схема: новая таблица создаётся автоматически на старте (`create_all`),
  миграция не нужна.
- Существующие витрины, что были только на диске, при следующем их задании
  админкой сохранятся в БД; после этого редиплой их больше не трогает.
- `VERSION` не поднимается (продолжение линейки 3.48.x).
