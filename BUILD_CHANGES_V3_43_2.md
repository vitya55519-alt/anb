# AnnaBot V3.43.2 — витрина показывает свежие карточки сразу, живые плитки играют

Скриншот владельца: на сетке Mini App снова СТАРЫЕ героини, хотя перерисованные
плитки уже задеплоены. Причина двойная: Telegram WebView держал каждый ассет всё
окно `max-age=3600`, а JSON `/webapp/api/characters` дополнительно кешировался
эвристически — сетка рисовала прошлогодний payload. Этот релиз чинит обе половины
и доводит живые плитки до рабочего состояния.

## 1. Ассеты витрины получили версию в URL
- `webapp_service.asset_version(character_id)` — штамп `<newest mtime>` папки
  референсов героини; пересборка плитки или новый live-клик меняют URL и клиент
  обязан забрать свежий файл вместо записи из кеша;
- `?v=` получили все ссылки payload'а: `photo`, `card` (webp-плитка), `live`
  (mp4-петля), полоса галереи `?i=&v=` и аватарки списка чатов;
- роуты `/webapp/photo`, `/webapp/gif`, `/webapp/live` переведены на
  `public, max-age=604800` — URL теперь content-addressed, длинный immutable
  кеш безопасен и бережёт трафик.

## 2. JSON витрины больше не кешируется
- `/webapp/api/characters` и ответ `/webapp/api/select` отдаются с
  `Cache-Control: no-store` — после деплоя сетка никогда не рисует stale-payload
  (старые карточки, пропавшие `live`-ссылки).

## 3. Живые плитки реально играют в WebView
- у `<video>` появился `preload="metadata"`;
- после рендера сетки каждой петле делается ручной `play()`-кикок — WebView не
  всегда уважает атрибут `autoplay`;
- IntersectionObserver ставит на паузу mp4-петли, ушедшие за пределы экрана, —
  восемь живых плиток не тормозят сетку.

## 4. Отказницы получают запасной моушен
- `LIVE_TILE_PROMPT_ALT` — медленный поворот головы и мягкая улыбка без рук;
- джоб `/livetiles` после отказа всех движков на «поцелуе» делает второй проход
  по всем движкам с запасным скриптом (maria отказывалась именно на поцелуе).
