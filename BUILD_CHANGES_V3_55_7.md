# V3.55.7 — Задания Mini App: засчитанный квест больше не показывает ошибку

## Симптом (скриншот владельца)
Лист «🎯 Задание» показывал тост «Не получилось ответить — попробуй ещё
раз», хотя все задания уже были помечены «✅ Выполнено · +5 внимания».
То есть +5 реально начислялся, но интерфейс сообщал об ошибке.

## Корень
V3.48.3 закрыл этот класс бага для **GET** `/webapp/api/feature` (обёртка
try/except, коммент прямо упоминал «raw 500 → бесполезное "Не получилось
ответить" на кнопке Задание»). Но **POST** `/webapp/api/feature/action`
обёртки не получил. Внутри `couple_service.claim_quest` происходит
`session.commit()` — после него +5 уже в базе. Дальше идут обычные
DB-записи (`track_event`, `save_message` эха в диалог, бонус-фото), и
транзиентный сбой на любой из них бросал исключение из не-обёрнутого
хендлера → aiohttp отдавал **500 с HTML-телом** → в SPA `r.json()` падал в
`catch (e) { toast(L.reply_err) }`. Пользователь видел ошибку при уже
засчитанном квесте.

## Фикс (`main.py`)
1. **Обёртка как у GET-брата.** `_webapp_api_feature_action` стал
   exception-guarded wrapper (`try: return await _impl / except:
   logger.exception + {'ok': False, 'error': 'temporarily_unavailable'}`);
   тело переехало в `_webapp_api_feature_action_impl`. Маршрут по-прежнему
   регистрирует публичное имя (обёртку). Это убираёт сырой 500/HTML и пишет
   настоящую причину в логи.
2. **Хвост после коммита — best-effort.** Как только `claim_quest` вернул
   результат (+5 закоммичен), `track_event` + `save_message` + бонус-фото
   обёрнуты в один `try/except`, и ответ **всегда** `{'ok': True, ...}`.
   Сбой эха/бонуса больше не превращает успешный квест в ошибку — SPA
   обновляет чек-лист («Выполнено») без тоста.
