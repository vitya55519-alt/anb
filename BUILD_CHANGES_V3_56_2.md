# BUILD CHANGES — V3.56.2 «Тормоз на картинках снят»

Дата: 2026-10-07. Идёт одним пакетом с V3.56.0 и V3.56.1 (до этого не задеплоены).

## Что захотел владелец
«Убери тормоза на фото генерации» — дневной бюджетный стоп картинок больше
не должен резать генерацию.

## Что сделано
- `config.py`: дефолт `SPEND_IMAGE_DAILY_BUDGET_USD` изменён с `2.0` на `0`.
  По уже существовавшей конвенции `0 = тормоз выключен` (`image_generation_allowed()`
  сразу возвращает True), так что код-механизм сохранён и включается обратно
  одной переменой окружения на Railway: `SPEND_IMAGE_DAILY_BUDGET_USD=5` —
  и лимит снова активен. Тормоз вспомогательного LLM ($1/сутки) не тронут —
  владелец его просил оставить.
- `services/spend_service.py`: строка «· тормоза: …» в /stats теперь пишет
  `выключен`, когда бюджет = 0 (раньше при выключенном тормозе она врала
  «$0.00 (активен)»).
- Проверки `if not spend_service.image_generation_allowed()` в роутере и
  Seedream-ноге оставлены как есть — при выключенном тормозе они никогда не
  срабатывают, а при включённом (через env) снова честно защищают бюджет.
- Леджер ImageSpend пишет каждый кадр спайси/fal и раньше, и теперь —
  «💸 сожжено на картинки сегодня» в админ-фиде продолжает считать по-настоящему,
  просто теперь это счётчик, а не кнут.

## Тесты
- Обновлён пин дефолта в `tests/test_v34418_spend_telemetry_static.py`
  (`"2.0"` → `"0"`). Остальные пины (`<= 0` ветка, наличие проверок) прошли без правок.
- Полный прогон: 16 failed / 1059 passed / 1 error — тот же baseline, ни одного нового провала.

## После деплоя
- На Railway ничего настраивать не нужно: отсутствие переменной = тормоз выключен.
- Если понадобится вернуть лимит: добавить `SPEND_IMAGE_DAILY_BUDGET_USD` с числом > 0.
