# BUILD CHANGES — V3.56.1 «Спайси рисует все сцены»

Дата: 2026-10-07. Идёт одним пакетом с V3.56.0 (ещё не задеплоены).

## Что захотел владелец
«Надо просто чтобы всё генерировал SpicyAPI — он лучше fai, именно сцены».
То есть разворот политики: не урезать SpicyAPI, а поставить его **в начало
очереди на каждую сцену** (качество выше, и цена ниже: $0.0345 против ~$0.04
за кадр на fal).

## Что сделано

### 1. Новый тумблер `PHOTO_SPICY_FIRST` (config.py)
- `PHOTO_SPICY_FIRST = os.getenv("PHOTO_SPICY_FIRST", "1") == "1"` — по умолчанию **включён**.
- Работает только при наличии `SPICYAPI_KEY`; без ключа всё остаётся старой
  fal-цепочкой (Gemini/OpenAI/Seedream) — ни один прежний тест без ключа не
  меняет поведение.
- Чтобы выключить на Railway: `PHOTO_SPICY_FIRST=0`.

### 2. Роутер фотографий (services/photo_service.py)
- Новая нога `_run_spicy_set(character, telegram_id, request, on_frame, *, character_id, frames)`:
  - переиспользует тот же промпт-конвейер, что и Seedream: `_build_prompt(..., seedream=True)`
    с замком личности и уровнем отношений;
  - референсы — канонические фото персонажа `{PUBLIC_BASE_URL}/webapp/photo/{character_id}?i=0` (лицо)
    и `?i=1` (тело), то есть i2i, личность не уплывает;
  - каждый кадр через `_spicyapi_render(SPICYAPI_IMAGE_MODEL, ...)`;
  - кадр кладётся в `GeneratedPhoto(data=..., provider='spicyapi', estimated_cost_usd=0.0345)`
    — байты едут в `.data` (тот же путь, что у Gemini-ноги);
  - если первый же кадр не вышел — `PhotoGenerationError('spicyapi', ...)`, роутер
    уходит на fal; если часть кадров уже вышла — набор отдаётся частично
    (меньше платим, меньше показываем);
  - каждое обращение пишется в `record_provider('spicyapi', ok, reason)` —
    админская статистика провайдеров видит и успехи, и пустые ответы.
- `choose_photo_provider`: при `PHOTO_SPICY_FIRST and SPICYAPI_KEY` сразу
  возвращает `'spicyapi'` (и для публичных, и для интимных сцен).
- `_run_routed_photo_set`: ветка `spicyapi` → при `PhotoGenerationError`
  логирует `from=spicyapi to=seedream45`, трекит событие и доигрывает набор
  через fal. То есть **пользователь никогда не получает пустоту из-за спайси**.
- Бюджетный тормоз (спенд-леджер из V3.56.0) проверяется ДО выбора провайдера —
  спайси-траты теперь считаются в `SPEND_IMAGE_DAILY_BUDGET_USD` по-настоящему.

### 3. Студия (main.py `_webapp_api_studio_picture`)
- Для обычных (не adult) генераций без загруженного референса перед fal
  `generate_custom_avatar` добавлена попытка i2i через SpicyAPI
  (`generate_private_photo_real` с категорией `studio`) — та же логика
  «спайси первый, fal подстрахует».

### 4. Тесты
- Новые: `tests/test_v3561_spicy_scenes_static.py` (5 статических тестов:
  тумблер+ключ, переиспользование промптов, форма GeneratedPhoto, 2 точки
  raise, порядок роутера spicyapi→seedream45, студийная попытка до fal).
- Обновлены пины под новую политику (старая fal-only стала политикой fallback):
  - `tests/test_v34419_fal_only_photos_static.py` — 2 runtime-теста теперь
    monkeypatch'ат ключ: с ключом ждём `spicyapi`, без ключа — прежний
    `seedream45`;
  - `tests/test_v3181_intimate_tier_static.py` — adult-роутинг пинится на
    ноге без ключа;
  - `tests/test_v3437_release_static.py` — счётчик `frames: int = PHOTO_SET_SIZE`
    5 → 6 (`_run_spicy_set` тоже принимает frames), функция добавлена в список.

## Что важно знать после деплоя
- Расходы на картинки перестанут быть «невидимыми»: каждый кадр спайси пишется
  в ImageSpend ($0.0345) и виден в админ-фиде (движок + цена) вместе с
  ежедневным счётчиком «💸 сожжено на картинки сегодня».
- Дневной тормоз `SPEND_IMAGE_DAILY_BUDGET_USD` по умолчанию $2 — при активном
  спайси он будет срабатывать раньше; если нужен больший поток, поднять
  переменную окружения на Railway.
- Если у спайси кончится баланс или ключ, картинки не пропадут — роутер молча
  уйдёт на fal и догенерит набор там.
