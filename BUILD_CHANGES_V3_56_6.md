# BUILD CHANGES — V3.56.6 «Мини-приложение открывается мгновенно»

Дата: 2026-10-07. Идёт одним пакетом с V3.56.5 (плотный поллинг SpicyAPI), обе ещё не задеплоены.

## Проблема (владелец)
«Грузится чат, задания, история — всё с задержкой, а фото нормально, сообщения
быстро приходят. Сама загрузка и прогрузка мини-приложения долго».

## Корень
1. **Страница приложения** — один файл 281 КБ, отдавался `FileResponse` с
   `no-cache`: без сжатия (FileResponse не умеет gzip), без 304-перевалидации —
   каждый открытый WebView качал все 281 КБ заново по мобильной сети (1–4 с
   только на скачивание, прежде чем что-то выполнилось).
2. **JSON-API** (`/webapp/api/characters`, `chats`, `chat_history`, `missions`
   — десятки КБ каждый) шли несжатыми и с `no-store`.
3. Сами ручки в порядке (N+1 в чатах починен ещё в V3.44.8) — тормозила сеть,
   не база.

## Что сделано (main.py)
1. `_webapp_index`: байды страницы кэшируются в памяти (инвалидация по
   mtime/размеру), gzip готовится один раз, выдаётся `ETag` + `Vary:
   Accept-Encoding`; повторное открытие — `304 Not Modified` вместо 281 КБ;
   первое — ~60 КБ gzip вместо 281 КБ.
2. Middleware `_webapp_gzip` на всё веб-приложение: сжимает JSON/текстовые
   ответы от 1 КБ (уровень 5), пропускает уже сжатые, маленькие и бинарные
   (фото/медиа идут как шли). Проверено на установленном aiohttp: content-type
   сохраняется, Content-Length пересчитывается.
3. Ожидаемая экономия: boot-трафик приложения ~×4–5 меньше, повторный вход —
   почти ноль.

## Тесты
- Новые: `tests/test_v3566_webapp_speed_static.py` (3 теста: кэш+ETag+gzip
  страницы, регистрация и guard'ы middleware, порядок регистрации).
- Функциональная проба aiohttp-паттерна — успешна.
- Полный прогон: 16 failed / **1070 passed** / 1 error — baseline parity
  (включая +2 теста V3.56.5).

## Замечание
Если после этого владельцу всё ещё будет «долго» — следующий кандидат
блокировки: синхронный SQLAlchemy крутится в одном event loop с ботом
(каждый запрос к БД на долю миллисекунд–миллисекунды блокирует всё). Лечится
переносом handler'ов в `asyncio.to_thread` — большой рефактор, делать только
по явному запросу.
