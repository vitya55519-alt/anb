# V3.57.7 — лимит 30 сообщений возвращён, фото-квоты не тронуты

## Запрос владельца

После деплоя V3.57.6 в `/stats` по-прежнему светилось `тормоза: LLM лимит $1.00/сутки
(активен)`, и владелец сформулировал итог так: «надо было убрать лимит LLM для
пользователей без премиума, оставить 30 сообщений в сутки». То есть бюджетный тормоз
выключить — а пользовательский гейт вернуть. Второй запрос («выделить больше лимитов на
фото для 3–6 уровня») после разъяснения снят: «нет, не трогай, кроме того, что я тебе
написал».

## Что произошло на самом деле

1. **`$1.00/сутки` после деплоя — это не код.** Дефолт в `config.py` стал `0` и коммит
   ушёл на Railway (пульнулся `41d2db3`, в снапшоте уже 112 пользователей против 109).
   Значит в Railway Variables лежит `SPEND_LLM_DAILY_BUDGET_USD=1`, и переменная
   перекрывает дефолт. Лечится в дашборде: удалить переменную (или поставить `0`) и
   Redeploy. Проверка в коде: `spend_service` считает тормоз выключенным при
   `SPEND_LLM_DAILY_BUDGET_USD <= 0`.
2. **3000/сутки было моим решением, а не твоим итогом.** В V3.57.6 я поднял
   `FREE_MESSAGES_PER_DAY` с 30 до 3000 и ты это одобрил в вопросе с вариантами, но
   текущая формулировка говорит обратное — возвращаю 30. Публикуемый тариф и код снова
   совпадают.

## Изменения

| Файл | Суть |
| --- | --- |
| `config.py` | `FREE_MESSAGES_PER_DAY` дефолт `3000` → `30`. Комментарий переписан: 30 — это тариф, который мы печатаем; ловушка `count < FREE_MESSAGES_PER_DAY` (0 = «писать запрещено всем», а не безлимит) осталась задокументированной |
| `services/legal_service.py` | значение не меняется, меняется только комментарий: ветка «без ограничения количества сообщений» теперь просто спит и включится, если потолок снова уедет ≥ 1000 |
| `webapp/index.html` | то же самое для строки магазина: `chatNote` печатает `30 сообщений/день`, ветка «без ограничения» остаётся запасной |
| `tests/test_v3551_premium_gates_static.py` | пин возвращён на `"30"` (имя теста `..._is_thirty` снова честно) |
| `tests/test_v3200_retention_static.py` | пин возвращён на `"30"`, в комментарии записана история 50 → 30 → 3000 → 30 |
